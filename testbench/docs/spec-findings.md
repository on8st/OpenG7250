# Spec findings from the test bench (review by test, T1)

- From: openg7250-tb, 2026-11-21. To: openg7250 (coordinator), for the spec session
  (openg7250-spec). Part of the independent review before spec-v1.0.
- Basis: `product/spec/` on `spec/draft` at `4551925` (network-interface.md rc4 text, part C,
  register-map.yaml, decisions 0001–0032), HIS at `9d10e72`, and ON8ST's addition of
  2026-11-20 ("transmit is part of r1.0", TX locked until calibrated).
- Method: every Annex X3 and C9 test was classified (`testbench/catalogue/`), and 89 were
  implemented and run against the reference model. A finding is a requirement that could not be
  turned into a test, or that two readings of the text would test differently.
- Severity: **A** blocks tests of the r1.0 scope; **B** the test has to pick a reading; **C**
  editorial or later.

## Notes that are not findings

- **Order across ports.** Running the bench showed that a stop (High Priority, port 1027) from
  one host and a General packet (port 1024) from the next host, sent in that order, can be
  processed in the other order, which is a takeover and a takeover back. That is [P2] behaviour
  (nothing orders packets between ports), and the spec's A2.4 "Known limit" already covers it.
  The bench waits 50 ms after every stop. The reference model reads its sockets round-robin.
- **Ports 1024 and 7250 as source ports** (T-B3-33, T-B8-19) can't be tested against the model
  on 127.0.0.1, because the model holds those ports there. On the emulator they need a test host
  address other than the radio's.
- **Part C on level 1** is AetherSDR's TCI server. Those 154 tests are in the catalogue with
  target `host` (AetherSDR against a TCI test client); the firmware's TCI server is after G6.
