# Test list and result format (v1.7)

- Status: **v1.7**, 2026-11-21. v1 was the proposal of openg7250-tb (2026-11-20). v1.1 folded in
  the first answers of the emulator side (openg7250-emu, relayed by openg7250): the address
  mapping of section 3, the fixture plan of section 4, and its four proposals (emulated-time
  timeouts, boot per test, artifacts, "not modelled" errors), all accepted. v1.2 folded in its
  answers to the open points of v1.1: the mapping confirmed, the `hw.trace` event schema, and
  `hw.input`. v1.3 took over the emulator's live trace file and its field names (`count`, not
  `events`). v1.4 takes over the emulator's proposal of pin modes and the levels `"z"` and
  `null`, so that "not driven" is no longer reported as "low", with the bench's rule per pin
  for them; `hosts[i].fixed_ports`; the DHCP fixtures and `net.endpoint`; the `boot` trace event
  and the replay at a trace start, with the point from which pins are judged (A3.6, 0045); the
  port rule for a shared machine. v1.5 adds the `key.log` fixture for the CW keyer timing of
  B10.5a (0046), in the shape the emulator side answered (paging, a cap, exact write times of
  the keying pins). v1.6 takes over the emulator's proposal of `net.log` (the image's sends and
  arrivals in emulated time), `eth.log` (MACRAW frames), `arp.peer` and `ip.conflict`, for the
  takeover timing of A2.4 and the address rules of A1.11 (0049). v1.7 adds `net.inject` and
  `time.wait`, so that judged bursts are placed and waits counted in emulated time. Changes
  are marked **(v1.1)** to **(v1.7)**. Each version only adds fields, apart
  from that one rename of a count nobody reads. A v1.3 reader keeps working if it treats an
  unknown level as "not driven".
- Purpose: the file that `product_run.py <elf> <tests> -o <result>` reads (`<tests>`), and the file
  it writes (`<result>`). The test bench uses the same two formats against the reference model
  and against the radio, so that results from all three compare per test id.
- Clean-room note: both files carry spec ids, test ids and observations of the network and of
  the emulated hardware pins only. They carry nothing about how the stock firmware behaves.
  The test code stays in `testbench/`. The emulator side runs it as a subprocess and does not
  import it.

## 1. Division of work

| Side | Does |
|---|---|
| `product_run.py` (emulator) | boots `<elf>` on the emulated main unit; relays the radio's network to addresses the test host can bind (section 3); offers **fixtures** (section 4) on a local control socket; for each test in `<tests>`, starts the test bench as a subprocess with an endpoint file; collects the per-test JSON it prints; writes `<result>` |
| test bench (`testbench/`) | implements every test id; talks to the radio only over the network (UDP 1024–1035, 7250, 7251) and, where a test declares it, through fixtures; prints one result object per test |

Command line of one test run, as the runner calls it:

```
python3 -m testbench run --endpoint <endpoint.json> --test T-B3-01 [--test …] --json
```

The test bench writes one JSON object per test (JSON Lines) to stdout, in the result-entry form
of section 5. Exit code 0 means it ran (whatever the verdicts); anything else means a test bench
error, which the runner records as `error` for the tests not reported.

**Boot (v1.1).** The runner boots the image once per test by default. A test list MAY say
`"boot": "per-list"`. The bench sets it only for a list it generated with
`list --boot per-list`, whose tests restore what they change. A test that installs a
calibration set or keys the transmitter leaves state behind and is never put in such a list.

## 2. Test list file (`<tests>`)

UTF-8 JSON, generated by `python3 -m testbench list` from the catalogue
(`testbench/catalogue/catalogue.json`), filtered by target and scope. The runner can also take a
hand-written subset.

```json
{
  "format": "g7250-testlist",
  "version": 1, "minor": 7,
  "spec":  { "branch": "spec/draft", "commit": "0e075f2" },
  "his":   { "commit": "d07627e" },
  "catalogue": { "commit": "<tb/main commit>", "sha256": "<of catalogue.json>" },
  "defaults": { "timeout_s": 30 },
  "boot": "per-test",
  "tests": [
    {
      "id": "T-B3-01",
      "title": "Broadcast discovery to 255.255.255.255:1024 yields exactly one reply.",
      "reqs": ["B3", "B3.2"],
      "target": "emulator",
      "scope": "v1.0",
      "needs": ["net.broadcast"],
      "timeout_s": 5
    },
    {
      "id": "T-B10-42",
      "title": "With record `tx` bit 4 = 0, DUC I&Q from the owner is discarded …",
      "reqs": ["B10", "B10.7", "0039"],
      "target": "emulator",
      "scope": "v1.0",
      "needs": ["hw.observe"]
    }
  ]
}
```

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | spec test id (Annex X3, part C C9), or a test bench id `T-<group>-L<nn>` for a test the bench adds where the spec has none (now `T-B10-L01`, `L07`, `L09`, `L11`); stable |
| `title` | yes | one line, for logs |
| `reqs` | yes | spec requirement ids the test proves (sections such as `B3.2`; decisions such as `0039`; `Annex P`; HIS sections such as `HIS 85`) |
| `target` | yes | the minimum environment: `host`, `emulator` or `needs-radio` (section 6) |
| `scope` | yes | `v1.0`; `not-v1.0` (for example 0030); `after-G6` (level 2); `from-M2` (wideband). The runner runs only `v1.0` unless told otherwise |
| `needs` | no | fixtures the test uses (section 4). If the runner lacks one, the result is `skip` with reason `fixture:<name>` |
| `timeout_s` | no | **(v1.1)** limit in **emulated** seconds; the result reports wall time separately |
| `params` | no | test parameters; opaque to the runner. **(v1.1)** `params.pending` lists the Annex P parameters the test needs measured (on the radio the result is `blocked` until the calibration set holds them). `params.package_slot_a` and `params.package_slot_b`: paths to Table M-4 packages of the firmware under test for slot A and slot B (built on the firmware side, `g7250-update-a.pkg` and `-b.pkg`), given by the runner; the bench reads them as opaque bytes (the 53-byte header, then the image of its length), parses only the header and sends both unchanged (the file exactly 53 bytes + image, signature length 0, hash right: Annex M "Package file"). `params.package_bad_hw_a`/`_b`, `package_bad_kind_a`/`_b`, `package_bad_entry_a`/`_b`: package files of the same form whose hash and header are right and whose image record names other hardware, the boot stage, or an entry point outside the slot (T-A1-88); the bench takes the one for the slot not running. The update tests use them where a trial must run; without them those parts are not run ("needs a real package", noted) and the test is judged on the rest |
| `boot` (list level) | no | **(v1.1)** `per-test` (default) or `per-list` |

## 3. Endpoint file (runner → test bench)

```json
{
  "format": "g7250-endpoint", "version": 1, "minor": 7,
  "kind": "emulator",
  "radio": { "ip": "192.168.73.10", "netmask": "255.255.255.0", "mac": "02:00:00:00:72:50",
             "connect": { "1024": "127.0.0.1:41024", "1025": "127.0.0.1:41025",
                          "1026": "127.0.0.1:41026", "1027": "127.0.0.1:41027",
                          "1029": "127.0.0.1:41029", "1035": "127.0.0.1:41035",
                          "7250": "127.0.0.1:47250", "7251": "127.0.0.1:47251" } },
  "hosts": [
    { "ip": "192.168.73.20", "in_subnet": true,  "bind": "127.0.0.1", "ports": [52000, 52099],
      "fixed_ports": [1024, 7250] },
    { "ip": "192.168.73.21", "in_subnet": true,  "bind": "127.0.0.1", "ports": [52100, 52199] },
    { "ip": "10.99.0.20",    "in_subnet": false, "bind": "127.0.0.1", "ports": [52200, 52299] }
  ],
  "broadcast": { "limited": true, "directed": "192.168.73.255",
                 "send_to": { "limited":  { "1024": "127.0.0.1:41124", "7251": "127.0.0.1:47351" },
                              "directed": { "1024": "127.0.0.1:41224", "7251": "127.0.0.1:47451" } } },
  "control": { "transport": "tcp", "address": "127.0.0.1:7290" },
  "fixtures": ["hw.observe", "hw.trace", "power.cycle", "reset.wdt", "ctrl.set", "time.scale"],
  "time_scale": 1.0
}
```

**Address mapping (v1.1).** The emulator gives the firmware any source address per datagram, but
the test host cannot bind those addresses without root. So:

- `radio.connect` (optional): for each radio port, the local address the bench sends to. A
  datagram the bench receives from that address is read as coming from that radio port (sender
  port demultiplexing, B2.4a). Without `connect` the bench sends to `radio.ip` on the spec ports.
- **(v1.4)** `hosts[i].fixed_ports` (optional), for example `[1024, 7250]`: ports the bench
  binds only when a test asks for that exact port (T-B3-33 source port 1024, T-B8-19 source port
  7250). An ordinary socket never takes one, also when it lies inside `ports`. A test that needs
  a fixed port not listed here skips with the reason.
- `hosts[i].bind` and `hosts[i].ports` [lo, hi] (optional): the local address and the port
  range the bench binds for host *i*. **(v1.2, confirmed by the emulator side)** Each local
  port *p* in [lo, hi] maps 1:1: the radio sees the source `hosts[i].ip`:*p*. A reply to
  `hosts[i].ip`:*p* arrives at local port *p* of `hosts[i].bind`, sent from the
  `radio.connect` address of the radio port it comes from. The ranges of hosts that share one
  local address do not overlap; the runner assigns them and writes them into the endpoint
  file. So a test that compares the owner's port in `IDENTIFY` (A1.5 I-4) with its own works
  unchanged. Tests that need a fixed source port (1024, 7250: T-B3-33, T-B8-19) bind that port
  and skip if it is taken or outside the range.
- `broadcast.send_to` (optional): where the bench sends a datagram meant as a limited or
  directed broadcast to a radio port (discovery and Set IP on 1024, identification on 7251).
  **(v1.2, confirmed)** A datagram to `send_to[kind][port]` reaches the radio as a limited
  (255.255.255.255) or directed broadcast on that port, from `hosts[i].ip`:*p* of the socket that
  sent it.
  Without it the bench sends to 255.255.255.255 or to `broadcast.directed` if those flags allow
  it, else the test skips with `fixture:net.broadcast`.
- `kind`: `refmodel`, `emulator` or `radio`. The bench uses it only for reporting and for
  tolerances the spec states per environment (B11.6a: "the reference model applies the rule
  exactly").
- `time_scale`: fixed 1.0 for now (emulator answer b).

The implementation is `testbench/testbench/net.py`.

**Local ports on a shared machine (v1.4).** The reference model and the emulator runner MUST
never share local ports. They run on the same machine.
- The emulator runner uses its per-run port base, plus the fixed source ports 1024 and 7250 on
  `hosts[0]`.
- The reference model uses its own port base: spec port *p* at base + *p*, control at
  base + 7290, bench hosts at base + 9000 … base + 9199. The default base is 20000, so every
  port lies below the ephemeral range (49152 and up on macOS), where client sockets take ports.
  `tools/run_refmodel.sh` picks the first of the bases 20000, 17000, 14000, 11000, 8000 whose
  every port is free, because the runner's per-run base can be anywhere else. The model
  writes the mapping into its endpoint file as `radio.connect` and `hosts[].bind`/`ports`, so
  the bench needs nothing else.
- The model never binds the spec ports 1024–7251 or 30000–38299. `--port-base 0` (the spec
  ports themselves) is allowed only when no emulator run can be going; `tools/run_refmodel.sh`
  refuses it without `G7250_ALLOW_SPEC_PORTS=1`.
- Before it starts the model, `tools/run_refmodel.sh` checks that every port it and the bench
  need is free (`tools/ports_free.py`), and it does not start if one is taken.
- Under a port base the bench's fixed source ports 1024 and 7250 lie outside the host range, so
  T-B3-33 and T-B8-19 skip against the model.

## 4. Fixtures (control socket)

The control socket carries JSON Lines, one request and one reply per line:
`{"op": "<name>", "args": {…}}` → `{"ok": true, "value": …}` or `{"ok": false, "error": "…"}`.
A runner offers any subset and lists it in `fixtures`, by the group name of the first column, by the operation names, or both (v1.4): the bench counts a group as offered when its name or any of its operations is listed, and an operation when it or its group is listed. **(v1.1)** The emulator's order of
delivery is given in the last column; the reference model offers the ones marked "model".

A fixture that answers `ok: false` with `"not in HIS: <name>"` makes the test `skip` with that
reason. The coordinator turns each such reason into a HIS question.

**(v1.4)** During a power cycle the runner answers any request at once with `ok: false`,
`"emulator not ready"`. The bench retries such a request every 0.2 s for up to 60 s; after
that the test is an `error` (a runner fault, not a verdict).

`hw.observe` snapshot. Keys and values are taken from the HIS 85 safe-state table only (latching
per HIS 85, emulator answer c):

```json
{ "t_us": 123456,
  "tr_lines": { "PF4": 1, "PF6": 0, "PC7": 0, "PH11": 0 },
  "spi1_a": { "oe_PA10": 1, "last_frame": null },
  "spi1_b": { "oe_PH10": 1, "last_frame": null },
  "atu_latch_writes": { "PD13": 0, "PG2": 0, "PG5": 0 },
  "pa_dac": { "reset_PB14": 0, "ch": [null, null, null, null, null, null, null, null] },
  "codec_reset_PB10": 0, "PD12": 0,
  "pins": { "PF4": { "mode": "output", "level": 1 },
            "PG2": { "mode": "output", "level": 1 },
            "PD5": { "mode": "analog", "level": "z" } } }
```

`last_frame` is the last byte latched into chain A (or chain B's 3 bytes), `null` if never
latched. `ch` holds the last 10-bit word per DAC channel, `null` if never written.
`atu_latch_writes` counts writes since the last `hw.trace start` (since boot without one).
**(v1.4)** `pins` gives every watched pin as an object with `mode`, `pull` (inputs only) and
`level`, as in a `gpio` event below. The pin fields of v1.3 (`tr_lines`, `codec_reset_PB10`,
`PD12`, the `oe_*` fields) stay, and their values may now be `"z"` or `null` too. The bench
judges the pins by `pins` when it is present, else by the v1.3 fields, with the rules below.
PH9 (the power hold, [HIS] HIS 20) in `pins` is judged in a snapshot only: held at 1 while the
firmware runs (decision 0029, part A scope). The trace does not judge it, since its level
during the boot is not in the HIS.

**Pin state (v1.4).** Every `gpio` event, and every entry of `pins`, carries:
- `mode`: `"output"`, `"input"`, `"af"` (alternate function) or `"analog"`;
- `pull`: `"up"`, `"down"` or `"none"`, for an input;
- `level`: `0` or `1` when something drives the pin: an output (push-pull; open-drain only
  when low), an input's pull (the pull level), or `hw.input`; `"z"` when nothing drives it
  (analog mode, an input without pull that is not driven, open-drain released without pull);
  for an `af` pin the level the peripheral drives, where the emulator models it, else `null`
  (unknown), never a guess.
A change of mode alone is also an event.

`hw.trace` **(v1.2)**. A trace records, from `start` to `stop`, JSON Lines in emulated time:

```
{"seq": 17, "t_us": 81234, "kind": "gpio", "pin": "PB14", "mode": "output", "level": 1}
{"seq": 18, "t_us": 81240, "kind": "spi", "bus": "SPI1", "cs": null, "data": "01"}
{"seq": 19, "t_us": 81300, "kind": "gpio", "pin": "PD5", "mode": "analog", "level": "z"}
{"seq": 20, "t_us": 81310, "kind": "reset", "cause": "power"}
```

- `seq` orders the events; `t_us` is microseconds since boot.
- `kind` `gpio`: one pin changed its level or its mode (the pin state of v1.4 above). Latch and
  output-enable edges are `gpio` events. **(v1.4)** `start` first emits the state of every
  watched pin as `gpio` events.
- `kind` `spi`: one transfer between chip-select edges on `SPI1` or `SPI2`; `cs` is the
  chip-select pin or `null`; `data` is the bytes as hex.
- `kind` `reset`: `cause` `power`, `wdt` or `software`.
- **(v1.4)** `kind` `boot`: `{"seq": n, "t_us": T, "kind": "boot", "at": "0x08020000", "pc":
  "0x0802xxxx"}`. The core executes its first instruction after a reset (power-on,
  `power.cycle`, `power.cut`, `reset.wdt`, software reset); `at` is the vector-table address it
  booted from (0x08020000, the boot stage), `pc` the reset handler address from that table, and
  `t_us` the emulated time of that first instruction. A reset during a trace gives a `boot`
  event right after the `reset` event.
- **(v1.4)** Replay at `start`: a trace first replays the last `boot` event and the boot-phase
  `gpio` events (their `t_us` before the start time, all within 10 ms of the boot), then the
  current state of every watched pin, then live events. The latch and strobe pins PA11, PH12,
  PD13, PG2, PG5 and PH9 are in that current state and in `hw.observe` `pins`. `start` returns
  `{"file", "t_us"}`: `t_us` is the emulated start time, where the replay ends. A runner that
  gives no `t_us` (a v1.3 runner) leaves the bench to take the boot + 10 ms.
- A reader MUST ignore an unknown `kind`.
- Pins: the HIS 85 safe-state items, plus any pin named in `start {pins: [...]}`.
- **(v1.3)** `start` returns `{"file": "<path>"}`; `stop` returns `{"count": n, "dropped": n,
  "file": "<path>"}`. `file` is the absolute path of that trace's JSON Lines file in the run
  directory, one file per `start` (`trace-<n>.jsonl`), written live (flushed per event), so the
  bench may read it at any checkpoint. The files are also listed under the test's `artifacts`.

The bench starts a trace at the beginning of every test, keeps the `file` from `start`, and at
each safe-state checkpoint of the test reads that file. At the end of the test it calls `stop`;
`dropped` > 0 makes the test `fail`, because its trace checks are then incomplete.

**From when (v1.4; spec A3.6, decision 0045).** The RF control pins of HIS 85 must be at their
safe-state levels no later than 20 µs after the boot stage's first instruction. Before that the
hardware and the vendor bootloader set them, outside the spec, and nothing there fails a test.
A test is judged in one of two ways:
- `since: boot` (T-A3-06, T-B10-L11): from every `boot` event's `t_us` + 20 µs on. At that
  moment each pin must already be at its level, then it must stay there. The replayed boot-phase
  events after that moment count.
- `since: start` (every other test): from the trace start's current-state snapshot on, so a
  boot-phase event is not judged once per test. A `boot` during the test is judged from its
  `t_us` + 20 µs.
A `hw.observe` snapshot taken before boot + 20 µs is not judged; the bench polls until it is
later.

**Rules per pin (v1.4).** The bench (`testbench/testbench/trace.py`) checks every event from
that point on, and the snapshot's `pins`. What each pin must do
follows the wording of the HIS for that pin. A pin the HIS wants **held** at a level fails on
any other state, `"z"` (not held) and `null` (unknown) included. A pin the HIS only forbids a
level for fails only on that level.

| Pin | HIS | Required | Fails on |
|---|---|---|---|
| PF4; PF6, PC7, PH11 (T/R lines) | HIS 85: RX levels, MUST be established | held at 1; held at 0 | any other level, `"z"`, `null` |
| PA10 (chain A OE) | HIS 85: inactive (high) until a frame with bit 7 clear is latched | held at 1 until such a frame is latched, then free | before that frame: 0, `"z"`, `null` |
| PH10 (chain B OE) | HIS 85: inactive (high) until a known frame is latched | held at 1 until a 3-byte frame is latched, then free | before that frame: 0, `"z"`, `null` |
| PD13, PG2, PG5 (ATU strobes) | HIS 85 (from `d199d33`): drive to the inactive level (high), never pulse | held at 1 | 0 (a pulse), `"z"` (a floating strobe is the risk the HIS names), `null` |
| PD12 | HIS 85: keep low | held at 0 | 1, `"z"`, `null` |
| PB10 (codec reset) | HIS 85, HIS 50: held in reset; reset is active low (AIC3204 datasheet) | held at 0 | 1, `"z"`, `null` |
| PD5 (USART2 TX) | HIS 70 item 2: UART idle level (high) or high-impedance, never low | never 0 | 0 only; `null` is noted in the detail, not failed |

Further: chain A bit 7 is clear in every frame latched into chain A (the last 1-byte SPI1
transfer before an edge of latch PA11; any edge, because the latch chip is a HYPOTHESIS in the
HIS). A frame with bit 7 set does not free PA10. The bias check uses the snapshot's
`pa_dac.ch`, because the HIS doesn't give the DAC word layout per channel. A v1.3 event without
`mode` is read with its integer level. The reference model has no raw events: `stop` returns
zero counts and no file. Its snapshot carries `pins` and two summary flags,
`spi1_a.bit7_ever` and `pa_dac.bias_nonzero_ever`, latched since the trace start.

`key.log` **(v1.5)**. The keyer of B10.5a is judged on mark and space lengths of ±1 ms and on
a 5 ms latency from a paddle edge, which the network cannot show: a `TX_STATE` push carries the
host's jitter, and emulated time can differ from wall time. `key.log` gives both sides of the
measurement on the radio's own clock.

- `start` → `{"t_us"}`: empties the log and records from now on. A `start` while running
  restarts (empties) it.
- `read {from_key?: n, from_hp?: m}` → `{"t_us", "key": [...], "hp": [...], "count_key",
  "count_hp", "dropped"}`: the entries from index `n` and `m` on (a page; the runner chooses
  its size), the totals so far and the entries lost to the cap. The bench reads page by page
  until it has `count_key` and `count_hp` entries.
- `stop {from_key?, from_hp?}` → the same as `read`, then stops.
- `key`: every change of the keyed state (`TX_STATE` bit 0, PA actually keyed) as `{"t_us",
  "on": 0|1, "tr": {"PF4", "PF6", "PC7", "PH11"}, "bias_nonzero"}`. The gate-cleared HIS 85
  does not single out one keying output, so the emulator takes **chain A bit 7** as the key
  signal: `on` = 1 while the frame latched into chain A (by PA11) has bit 7 set with its output
  enable PA10 low ("a T/R relay or PA-enable line", HIGH), edges timed from the PA11 latch and
  PA10 writes. `tr` (the four T/R levels; RX levels PF4 1, PF6, PC7, PH11 0: levels VERIFIED,
  function HYPOTHESIS) and `bias_nonzero` (any of PA DAC bias channels 2, 7, 8 non-zero) come
  with each entry, so the judgement can change without an emulator rebuild. The bench takes
  `on` and checks at every key-on that `tr` has left the RX levels and `bias_nonzero` is true
  (a disagreement fails, with its own reason); at a key-off they are not judged, since the
  relays return only after RF is gone (A3.9a item 1) and stay in transmit between CW elements
  (A3.4d). Which signal the radio keys with is fixed later with the measured values (A3.9a).
  On the reference model, its own keyed state, with `tr` and `bias_nonzero` following it.
- `hp`: every High Priority packet received on radio port 1027 as `{"t_us", "seq", "b4",
  "b5"}`: bytes 0–3 (the sequence number), byte 4 and byte 5 (CWX and the paddle bits). On the
  emulator `t_us` is the time the datagram enters the CH394 socket receive buffer (first
  visible to the image).
- Every `t_us` is on the clock of the trace and `boot` events (section 4, `hw.trace`).
- A cap (about 100 000 entries each) with `"dropped": n`. Dropped entries fail the test, as
  for `hw.trace`.

The bench measures marks and spaces between `key` events and latencies from the `hp` arrival
of the packet with the edge, so its own pacing does not enter the verdict. It plans each paddle
edge at least 0.2 T from the keyer's decision points and checks afterwards that it arrived
there; if one did not, the test is an `error` with reason `pacing: …`, not a verdict. Until the
image keys (record `tx` bit 4 = 1), these tests are `blocked` on the calibration set.

`net.log` **(v1.6)**. `start` empties the log and records from now on; `read {from?: n}` →
`{"t_us", "count", "dropped", "entries": [...]}` from index `n` on (paged); `stop` reads, then
stops. Each entry: `{"t_us", "dir": "to_radio"|"from_radio", "socket", "radio_port", "peer":
"ip:port", "len", "head"}`, `head` the first 16 payload bytes in hex; a datagram the radio
did not take is an entry `{"t_us", "dir": "dropped", "socket", "radio_port", "reason"}` (T-B5-20
fails "no loss in the burst" on one for port 1027 inside a judged burst, 0054). `to_radio` `t_us` is when
the datagram is placed in the socket receive buffer, `from_radio` `t_us` when the image's SEND
executes, both on the clock of `hw.trace`. Cap and `dropped` as `key.log` (dropped fails the
test). The bench judges radio behaviour in time (the copies about 10 ms apart, the 5 s notice
window) on these stamps where `net.log` is offered; otherwise on the host clock, strictly only
where that is the radio's clock (the reference model), loosely and with a note on an emulator.

`eth.log` **(v1.6)**. The same paging, for the MACRAW frames of socket 0: `{"t_us", "dir",
"len", "dst", "src", "ethertype", "arp"?: {"op", "sha", "spa", "tha", "tpa"}, "hex"?}` (`hex` for
a frame that is not ARP). Frames the image sends in MACRAW go only to this log and to
`arp.peer`, not onto the host network.

`arp.peer` and `ip.conflict` **(v1.6)**. `arp.peer` is a simulated other host: it answers the
radio's ARP probe for its address (`answer_probe`), defends it (`defend`), or announces it
(`announce`, `count` times). `ip.conflict raise` is the exact tool for a conflict interrupt;
`auto` is the emulator's model of the chip (marked as an assumption). Emulator assumptions,
marked in its answers: the MACRAW length is the frame alone (switchable); the chip does no ARP
of its own in UDP mode; the MAC filter bits of Sn_MODE are applied per the datasheet.

`hw.input` **(v1.2)**. The level is electrical (0 or 1). The bench drives both levels on every
pin, because the HIS doesn't give the active level. Edges reach the interrupt controller as from
a real input.

## 5. Result file (`<result>`)

```json
{
  "format": "g7250-testresult", "version": 1, "minor": 7,
  "testlist": { "sha256": "…" },
  "subject":  { "kind": "emulator", "elf_sha256": "…", "fw_version": "0.1.0+12" },
  "runner":   { "name": "product_run.py", "version": "…", "emulator_commit": "…" },
  "testbench": { "commit": "…" },
  "started": "2026-11-21T21:00:00Z", "finished": "2026-11-21T21:04:10Z",
  "results": [
    { "id": "T-B3-01", "status": "pass", "duration_s": 0.21, "wall_s": 0.9,
      "reqs": ["B3.2"], "checks": [ {"name": "one reply", "ok": true, "detail": "1 reply in 1.0 s"} ],
      "artifacts": { "console": "T-B3-01/console.txt", "network": "T-B3-01/network.pcapng" } },
    { "id": "T-A3-11", "status": "skip", "reason": "fixture:sensor.set" },
    { "id": "T-A1-29", "status": "blocked", "reason": "pending:P-RF-3" },
    { "id": "T-B6-11", "status": "error", "reason": "not modelled: ADC/test tone" }
  ],
  "summary": { "pass": 0, "fail": 0, "skip": 0, "blocked": 0, "error": 0, "not_run": 0 }
}
```

| `status` | Meaning |
|---|---|
| `pass` / `fail` | verdict; a `fail` lists at least one check with `ok: false`. A `pass` may carry a `reason` naming parts of the test that could not run in this environment |
| `skip` | not run: fixture or host address missing, or scope not selected (`reason` says which); also a test that ran but could show nothing of its claim. A failed check makes either a `fail` |
| `blocked` | cannot be decided yet: the test needs an Annex P parameter not yet set (**(v1.1)** `reason`: `pending:<P ids>`, was `TBD:<HIS ids>`) |
| `error` | the test or the runner broke (exception, timeout); `reason` holds the message. **(v1.1)** An environment limit of the emulator gives `error` with `reason` starting `not modelled: <peripheral>/<register>`: not a verdict on the firmware |
| `not_run` | listed but never started (runner aborted) |

**(v1.1)** `duration_s` is emulated time and `wall_s` wall-clock time. `artifacts` (optional)
names files relative to the run directory.

Runner exit code: 0 if there is no `fail` and no `error`, 1 if there is a `fail`, 2 if there is an `error`.

## 6. Targets

| `target` | Runs where | Example |
|---|---|---|
| `host` | on the host alone, against the reference model, or checks host software (g7250ctl, an AetherSDR backend) and spec artefacts; no firmware | conditions the spec marks "reference model", the calibration set (T-A1-63), the range edges with TX unlocked (T-A1-65) |
| `emulator` | network black box against the firmware in the emulator, and also against the reference model; fixtures as declared | discovery, register map, write rejections, TX frozen (T-B10-41, T-B10-42) |
| `needs-radio` | the real radio, under the safety rules of HIS 90 (dummy load on both ports); a keying test runs only once its `params.pending` parameters are set (Annex P "Tests") | RF measurements, real link renegotiation, ICMP behaviour of the CH394Q, relay timing |

A test with target `emulator` is also run against the reference model. A test with target
`host` is not sent to `product_run.py`.
